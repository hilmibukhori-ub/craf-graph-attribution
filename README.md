# CRAF: certified minimal graph-property explanations for graph neural networks

Research code for **CRAF** (Certified Relational Attribution Frontier) and the preceding **RUSA**
studies (Robust Utility and Specificity Assessment).

CRAF asks which combinations of label-free graph properties (communities, feature-similarity
clusters, clustering, two-hop volume, ...) are *sufficient* to explain what a graph neural network
gains from the observed graph. For every combination in a declared lattice it builds
degree-preserving null graphs that keep those properties, retrains the model, and

* certifies each combination as **insufficient**, **sufficient** or **inconclusive** under
  family-wise error control (Holm over all directional hypotheses);
* returns a **certified-minimal** and a **possibly-minimal** set that bracket the true frontier of
  minimal sufficient combinations with probability at least 1 − α, without assuming that preserving
  more structure moves performance monotonically towards the real graph;
* optionally reallocates replicates in two stages (minimax-power allocation with an inverse-normal
  combination test), which keeps the guarantee and reduces cost.

The method, its guarantees and pseudocode are in [`docs/craf_math.md`](docs/craf_math.md); the
underlying estimands and inference are in [`docs/rusa_mathematical_spec.md`](docs/rusa_mathematical_spec.md).

## Repository layout

```
src/rusa/
  craf/            lattice, three-way Holm certification, frontier sets, adaptive allocation
  nulls/           ER, degree-preserving and stratum-preserving swap nulls; admissibility audit
  inference/       one-sided tests, combination tests, allocation, certificates
  models/          SGC-ridge, GCN, GraphSAGE, MLP (plain PyTorch)
  data/            synthetic worlds with known frontiers
  realworld/       real-graph loaders, label-free attributes, replicate pools, analysis
  evaluation/      pools, procedures and comparators used in the simulation studies
scripts/           pool runners, analyses, report and figure generation, freeze tool
scripts/hyperion/  SLURM batch files used on the compute cluster
configs/           one YAML file per study (frozen before each run)
tests/             unit and regression tests (pytest)
docs/              protocols (frozen before each run), reports, mathematical notes
outputs/           analysis tables, reports, freeze manifests and checksums of the raw pools
```

## Installation

Python ≥ 3.9 with NumPy, SciPy, pandas, PyYAML and PyTorch (CPU is sufficient). NetworkX is used for
Louvain communities and clustering coefficients; numba is optional (faster swaps, bit-identical
results); matplotlib is only needed for figures.

```bash
pip install -e ".[test,fast,plots]" networkx
python -m pytest -q
```

### Running a real-graph study

```bash
export RUSA_DIR=/path/to/run/directory      # a copy of this repository with data/raw/ filled in
cd "$RUSA_DIR"
python scripts/freeze_plan.py --config configs/phase3e.yaml            # hash-freeze the plan
python scripts/prepare_phase3c.py --config configs/phase3e.yaml        # label-free attributes + admissibility audit
python scripts/run_pool_3b.py --config configs/phase3e.yaml --list     # number of tasks
python scripts/run_pool_3b.py --config configs/phase3e.yaml --task-id 0
python scripts/run_phase3b.py --config configs/phase3e.yaml --workers 8
python scripts/make_report_3b.py --config configs/phase3e.yaml
```

On a SLURM cluster the same steps are wrapped in `scripts/hyperion/*.sbatch` (set `RUSA_DIR`, and
adapt the account, partition and module lines to your cluster). Paper figures are produced from the
analysis outputs with `python scripts/make_paper_figures.py`.

## Reproducibility

* All randomness derives from hierarchical seeds keyed by (master seed, dataset, replicate, purpose,
  element, draw), so any split, model seed or null draw can be regenerated individually.
* Before each run, `scripts/freeze_plan.py` hashes the configuration, all source and batch files, the
  protocol and the raw data into `outputs/<study>/FREEZE.json`; every compute task verified the
  manifest before running. The manifests describe the files as they were run on the cluster: each
  study ran in its own directory with the code of that time, and the batch files in this repository
  differ from the frozen ones only in the e-mail and directory placeholders.
* Raw result pools are kept on the compute cluster; their SHA-256 checksums are in
  `outputs/<study>/POOL_SHA256SUMS.txt`.
* Results in the reports were produced on Linux with Python 3.10, PyTorch 2.1.2, NumPy 1.24,
  SciPy 1.10, pandas 1.5 and NetworkX 3.0, one CPU thread per task.
